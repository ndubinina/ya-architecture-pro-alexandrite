## Места для логирования
Системы для сбора логов:
- Shop API
- CRM API
- MES API

Что логируем на INFO (кто инициировал действие, во сколько, результат, trace_id):
- действия, которые должны были провести к изменению статуса заказа (создание заказа, загрузка модели для расчета, расчет стоимости заказа, согласование заказа CRM и тп)
- начало и завершение расчета стоимости заказа

Что логируем на WARN:
- неверные попытки залогиниться (кто инициировал, trace_id)

Что логируем на ERROR(stack_trace, trace_id, время, кто инициировал):
- бизнес-ошибки - расчет стоимости завершился ошибкой
- ошибки входных данных
- ошибки подключения к БД, к S3

Чувствительную информацию не логируем (маскируем), чтобы можно было на продовом стенде включить этот уровень для анализа проблем

## Мотивация
Добавление логирования необходимо, чтобы иметь данные для анализа жалоб клиента, разобрать конкретный кейс зависания заказа. У поддержки будет инструмент для анализа обращений клиента.

В первую очередь логирование надо добавить в Shop API, чтобы отслеживать момент создания заказа. После того, как заказ попал в БД частично можно проанализировать по данным из БД. В MES API для анализа, как с заказом работал оператор. И в CRM API для анализа, как с заказом работал сотрудник CRM.
Необходимо логировать исключения и ошибки - с идентификатором заказа и детализацией ошибки.

## Предлагаемое решение
[Схема предполагаемого решения](./../jewerly_c4_model.drawio)

### Безопасность
- чувствительные данные не логируем (маскируем), на всех уровнях, кроме TRACE
- доступ к чтению логов есть у ограниченных групп пользователей - разработчики, поддержка
- доступ на изменение уровня логирования ограничен

### Политика хранения
Отдельные индексы под дням последних 60 дней, логи старше 60 дней храним в холодном хранилище (на s3). Логов примерно 60 Кб на один заказ.

### Система анализа логов
Логи сохраняем в формате Json для возможности в дальнейшем добавить анализатор логов.
В Kibana в дальнейшем можно настроить анализ и алерты в случае роста ошибок или критичному изменению объема ключевых логов
